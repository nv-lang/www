Nova releases

Nova Oracle 0.1.0 is the Rust-based compiler distribution. Nova Carina 0.2.1 is the published Windows x86_64 alpha of the self-hosted compiler. Both are early alpha releases: APIs and language features may change, and compatibility is not guaranteed.

Nova Oracle 0.1.0 (alpha)

Oracle compiles Nova to C, then to native code. It includes the nova CLI, standard library and C runtime; the binary bundles also include nova-lsp. The Windows bundle was smoke-tested after a clean extraction with the default Boehm GC. The Linux bundle was smoke-tested after a clean extraction on x86_64. A C toolchain and Boehm GC development files are required to build Nova programs on Linux.

Nova Carina 0.2.1 (alpha)

Carina is the compiler written in Nova. This Windows x86_64 alpha was built from source revision 3729abcce: the published Oracle 0.1.0 first built stage A, stage A emitted C, and Clang compiled that C into the released stage-B1 executable. For this source, B1 and the newly pinned seed reach the same C-level fixed point: 13,250,302 bytes, SHA-256 (25c5404f1e8e175652f19c9ca6cb03d29de82cee70a7cd9f4258c6724115c8a0). The required CI gate still uses Oracle; migration away from Oracle is in progress. This C-level result does not claim Oracle-free bootstrap or native executable equality with a stage B2, Linux support, or package-ecosystem readiness (planned for 0.3). Building Nova programs still requires an external C toolchain. Historical Boehm GC headers and Oracle/run-2 libraries are documented in the linked receipt and release notes. The linked release-notes.md is a snapshot from before this verification; see the current release body for the update.

Why 0.2.1? 0.2.0 established a fixed point for an earlier accepted source revision. 0.2.1 pins a new seed to revision 3729abcce and verifies its C-level fixed point on that source; the older seed's separate successful emit does not establish the same fixed point.

Nova Carina 0.2.0 (alpha)

Carina is the compiler written in Nova. Its accepted Windows x86_64 A → B → C bootstrap produced byte-identical B and C executables and byte-identical generated C. The Windows archive contains that saved stage-B novac.exe, not a newly rebuilt binary. The 0.2 milestone proves self-compilation, not readiness of the wider package ecosystem; that is a 0.3 criterion. No Linux Carina binary is included in 0.2.0: the Linux CI build is not a Linux double-build receipt.
